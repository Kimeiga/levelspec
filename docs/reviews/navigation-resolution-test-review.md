# Navigation resolution: independent preimplementation test review

Date: 2026-11-03. Scope: expose horizontal navigation cell size through the repository CLI, shared browser reviewer, and deterministic reconstruction runner. Applied `write-readable-typescript` and `maintain-tests`. This review does not implement production changes or certify browser behavior.

## Findings that determine acceptance

1. **Compilation and runtime validation must use the same explicit value.** `src/cli/pipeline.ts`, `viewer/worker.ts`, and `src/reconstruction/loop.ts` currently call `validateForRuntime` with `sealed: true` and no cell override. Validation independently bakes open navigation; setting only compilation would silently restore 0.125 m. A compilation diagnostic can also prevent later validation, so using the override only at validation is insufficient. Test the completed report and exported runtime, not just a compile option.
2. **A passing premap report is not the doorway assertion.** The retained R14 diagnostic at `generated/dai2-daiban/multiview-model-r14/navigation-resolution-diagnostic-01/results.json` reports `passed: true` at both 0.125 and 0.0625 m. At y=9.325, ordinary movement from x=7.5 reaches only about 7.732 with the former and reaches x=8.35 with the latter. Geometry hash and the 0.25 m radius / 1.8 m height player are identical. This supports a resolution control; it does not establish whole-building traversal or photographic correctness.
3. **Cache identity already includes cell size.** `src/vector/validate.ts` includes cell, vertical cell height, sampling, player, movement, geometry and sealed state in its cache key. Optional water and closed-state validation spread the options. Preserve that contract; do not add cache exceptions or change player dimensions, tolerances, sampling, collision, or acceptance thresholds.
4. **Record the effective setting even when no candidate passes.** Current reconstruction attempt/result JSON primarily records scores and booleans; navigation settings otherwise survive in a valid candidate's runtime export. An invalid/nonexportable run still needs its effective cell setting recorded. A source XML or visual GLB alone does not reproduce a navigation setting selected outside XML. Default and explicit settings must be distinguishable through a documented replay command or equivalent run configuration.
5. **Browser selection is applied configuration, not a visual toggle.** A change must rebuild navigation, visibly mark old geometry/navigation stale, disable walking until the new result is ready, and discard superseded worker results. Invalid input must leave the previously applied setting and valid model intact. A source refresh, retry, and shared camera/walk link must retain the setting; restoring a walking pose must revalidate support against the current result.
6. **Verify the active website path before expanding scope.** Current `website/main.ts` mounts `review/app.ts` with `viewer/worker.ts`; it does not load a baked navigation artifact. Existing baked-lighting helpers do not establish a navigation fallback. The shared worker needs website acceptance. If another active entry point does consume baked navigation, a mismatched setting must trigger a real rebake or an explicit unsupported/error state, never a label claiming the selected resolution while using old navigation. Do not add tests for an imaginary fallback.

## Public option contract

Use meters, explicitly horizontal resolution, with default 0.125. The proposed inclusive public range 0.025–0.5 m is acceptable as a product input bound, **not a resource guarantee**. Reducing 0.125 to 0.025 produces roughly 25 times as many horizontal grid cells for the same extent; finer settings can fail existing resource limits. Keep those failures visible and cancellation/recovery intact. Do not silently clamp, coarsen, or change the player to obtain a result. Existing low-level API remains finite-positive and unrestricted by this new public bound.

Reject missing/empty values, nonnumeric strings, NaN, infinities, zero, negatives, and values outside the range at the public input boundary. Accept meaningful decimals such as 0.0625 without rounding. Test both inclusive endpoints. Invalid CLI options should produce the existing usage failure before starting preview or replacing build/reconstruction output. A malformed shared URL must produce a visible configuration error rather than silently use the default. Keep vertical cell height 0.05 and sample spacing 0.5 unchanged.

## Minimum meaningful verification

- **Domain/navigation and walk:** Use one small real compiled doorway fixture with fixed, independently stated clear dimensions, the normal player, and start/end points on opposite sides. Establish coarse failure and fine success with ordinary constrained movement. At fine resolution, reduce clear width below the player's diameter or fill the aperture and assert crossing remains blocked; include a low-headroom obstruction if it shares the fixture cleanly. Assert document/player/physical geometry remain unchanged. Avoid full R14 as a unit fixture, synthetic nav triangles, exact triangle counts, or a test satisfied by `passed: true`. Existing `tests/vector-navigation.test.ts` and `tests/review-walk.test.ts` own these behaviors.
- **Configuration propagation:** On real compilation, compare omitted default versus explicit 0.125, then 0.0625; verify reported settings and changed cache identity without depending on a specific hash. Validate with closed dynamic geometry and confirm open/closed settings agree while genuinely closed routes remain rejected. Existing cache/body tests need not be duplicated.
- **CLI finite commands:** Extend `tests/vector-cli.test.ts` with subprocess validate/build cases on the same small fixture. Assert selected setting in stdout report and saved runtime/report; omitted default remains 0.125. Parameterize representative invalid inputs, inclusive endpoints, and recovery with a subsequent valid invocation. Preserve exit/output contracts and existing exports on failure.
- **PR13:** Exercise the real deterministic CLI on frozen XML with explicit 0.0625 and omitted default. Check iteration/result configuration, the actual navigation settings in a valid runtime export, and unchanged image-evidence gates. Missing photo evidence must not become accepted merely because navigation improves. Include rejected-input output preservation and an unsuccessful-run configuration record. Existing `tests/vector-reconstruction-output.test.ts` owns process/output behavior; domain reconstruction tests can cover option propagation without another mock runner.
- **Browser acceptance, separately required:** Use the actual UI and worker to select a value, await observable readiness, inspect effective settings, start a supported walk, change resolution and verify stale walking is disabled, then reload a shared URL containing camera/walk state. Verify source refresh and retry preserve the selected value, malformed input is visible, and a later valid value recovers. Run the local/CLI preview flow and a focused website adapter smoke test; do not duplicate all domain permutations in browsers. A preview URL string unit test alone cannot prove worker propagation or movement.
