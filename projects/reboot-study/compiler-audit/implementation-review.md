# Independent compiler audit review

Reviewed the current compiler, CLI publication path, producer physical-route checks, both audit scripts, and the named authoring generators. This is a review of existing behavior and proposed ownership, not acceptance of an engine patch. No compiler or map source was modified by this reviewer.

The core findings are supported. I independently reran both scripts into `generated/reboot-compiler-audit/independent-connection-review/` and `generated/reboot-compiler-audit/independent-construction-review/`. The results agree with the original observations. The existing passing suite reported by the coverage reviewer is separate evidence; I did not rerun that suite.

## Findings

1. **High priority: route multiplicity is not validated against the physical mouths in the ordinary compiler/CLI path.** `src/architecture/compiler.ts:1933` adds an edge for every connection once both floor IDs survive compilation. `src/vector/validate.ts:28` assigns another unit of capacity for every repeated edge, and `src/vector/validate.ts:560` combines that semantic count with a single actual navigation path. `src/cli/pipeline.ts:85` calls this compiler and `validateForRuntime` at line109, without the producer's later physical check. Both duplicate-mouth and blocked-mouth-with-alternate-route cases pass with `disjointRoutes:2`, despite there being one physical entrance resource. The latter path actually detours to y6.25 and measures10.632m. A shared physical route validation contract belongs below the separate CLI/producer entry points. Reuse/refactor the existing algorithm rather than creating another per-map check.

2. **High priority: explicit invalid connection path references are accepted.** `src/architecture/format.ts:344` retains `path`, while the compiler loop above never resolves it. This deserves a source-linked reference diagnostic independently of navigation and route assertions. The producer is not a complete fix: `src/authoring/physical-routes.ts:39` silently drops absent/unresolved paths, then `requirePhysicalRoutes` at line353 only rejects unsatisfied routes. I additionally removed the route from the missing-path example: compiler, runtime validation, and producer all passed. The source and observation are retained as `independent-connection-review/missing-path-without-route.{aml,json}`. Promoting producer evidence alone would leave this hole.

3. **The tall lightwell remnants are an authoring/generator defect, with useful existing compiler support.** `projects/ninefold-reboot/layout-l02/draw-layout.py:166` assigns9.5m to all ground boundary walls; lines180–189 lower only intervals intersecting buffered upper domains. Pieces outside those masks retain the tall literal height. The compiler accurately preserves it. The reduced case's final wall top is9.5m with no diagnostics; changing the source to `base-floor`/`top-floor`/`span-floors` produces6.650000095m below a6.9m roof of0.25m thickness. `src/architecture/walls.ts:113` invokes this existing anchor behavior. It is not automatic building ownership: walls in a roof hole need appropriate ownership/splitting or a deliberately different top. Anchors should expose that ambiguity, not silently choose a neighboring roof.

4. **Missing roof-step enclosure is a missing architectural assertion, not a demonstrated Boolean or extrusion error.** The reduced omitted-fascia case compiles without diagnostics and leaves the test segment open. An explicitly anchored fascia gives z3–5.75 and blocks the same segment. This proves the current constructor can make that piece; it does not prove an entire building shell is closed. `<room>` is explicitly metadata (`src/architecture/volumes.ts:15`). A future shell/envelope declaration could state owned floors/roofs and intentional apertures, then report missing closure. Automatically filling every stepped roof boundary would change intentional courtyards, clerestories and cross-volume sightlines. Last Light's original omission was already present in its developed geometry; L02's generator now explicitly constructs roof seams at `projects/last-light-reboot/planning/develop-layout-l02.py:89`.

5. **Headroom improvements should target attribution and usable assertions.** Current clearance assertions already report both the required passage and offending lintel in the reduced case (`src/architecture/volumes.ts:176`). Navigation coverage already retains failed coordinates and measured clearance (`src/vector/navigation-coverage.ts:148`), but its emitted diagnostics aggregate by floor and reason (`src/vector/validate.ts:154`) without blocker ownership. Carrying contributing object IDs and clustered inspection bounds into those diagnostics is a justified usability improvement. Do not describe this as a missing headroom detector; the prior reboot reports already caught headroom and width failures.

## Boundaries for the proposed changes

- A connection path is a mouth span, not a travel centerline. Define a usable body-sized crossing through that span, including floor support, direction and stance as applicable. Requiring every endpoint of the span to be walkable would reject ordinary guard/jamb margins. Exact route itineraries would require their own explicit contract; a from/to route is currently allowed to take a detour.
- The producer algorithm is conservative entrance-resource independence. It samples crossings, clips navigation by floor ownership, and can undercount; its own method statement at `src/authoring/physical-routes.ts:348` says so. It is not continuous capsule collision, tactical independence, or target-engine gameplay proof. Preserve its budgets, cancellation and boundary cases when sharing it.
- Existing wall joins operate on matching endpoint incidents within an assembly (`src/architecture/joins.ts:15`, `src/architecture/compiler.ts:867`). Arbitrary extrusions and near-coincident endpoints are outside that contract. The recent tiny seams alone do not demonstrate a broken native wall-join algorithm or justify global snapping.
- The audit scripts are appropriately small public-entry-point observations. Their segment test is a line/triangle witness, not a body sweep; the simple blocker dimensions provide the rest of the reduced-case argument. They intentionally record behavior rather than enshrine failures as permanent test expectations. Future production fixes need behavioral regressions for the intended corrected contract.

Recommended order: validate explicit connection references and unify physical route requirements; improve obstruction attribution; use existing anchors and clearances in authoring; then design an explicit envelope contract if automatic closure remains a recurring need.
