# Kowloon compile profile: November 12, 2026

The updated frozen demo compiled successfully in **244.777 seconds**, with no
diagnostics. Texture and shadow resolution were unchanged. This is one fresh
process measurement, not a median or a before/after speedup. The user subsequently
authorized aggressive algorithm changes, including appearance changes, while the
resolution constraint remains in force. See the subsequent [implementation and benchmark report](kowloon-optimization-2026-11-12.md).

## Measurement boundary

Node 24.12.0, Apple M4, macOS arm64, 16 GiB RAM. The benchmark includes compilation
and navigation; it excludes module loading, AML parsing, export, browser upload,
and shadow rendering. Other machine activity was uncontrolled. Assistant-owned
benchmarks ran sequentially. A 342-file source/asset snapshot isolates concurrent
visual-development edits; its fingerprint remained unchanged during both runs.
Subsequent workspace changes are recorded separately in the evidence JSON.

The harness uses the demo builder's existing budgets: 6,000,000 triangles,
131,072 charts, 96 Mi channel-texels and 768 MiB. At the initial baseline, the stock profiling CLI used smaller defaults and failed at 74,491/16,384 charts before baking. Its two
failed preflights (12.357 and 23.810 seconds) are not completed compile timings.
Matching the builder's budgets in the disposable harness does not change fidelity. The implementation now shares these budgets between the builder and profiling CLI.

The result contains 505,382 triangles, 1,474,018 vertices, 74,491 receivers,
90,610,824 allocated channel-texels, and 12,961 generated images occupying
86,894,322 encoded bytes. A channel-texel counts a pixel separately for each
color, metallic/roughness, or normal image. A receiver is a geometry patch with a
procedural appearance recipe and coordinate mapping; it is not necessarily an
object or a unique texture. Multiple receivers already share raster groups.

Earlier November 11 measurements used 222,915 triangles, 3,402 receivers and
4,037,444 channel-texels. Those are different workloads, so their times cannot
establish a code-only regression ratio. Buildings account for 72,854 of the
current receivers; individual component faces explain much of the count.

## CPU evidence and causes

A separate instrumented run was cancelled after 240.012 seconds during
rasterization. Its stages were 11.502 seconds dressing, 89.770 seconds validation,
4.289 seconds decoding and **134.051 seconds of partial raster work**. It also
contains a brief debugger pause. Its sampled times identify hot paths; they must
not be added to or substituted for the completed run's stage timings.

`createPipeRunoff` accounts for **79.576 seconds of inclusive sampled time** in
that partial profile. Validation samples each chart and thereby initializes lazy
pipe runoff fields. The label "validation" hides material preparation: simply
moving it to another stage would not improve total time.

The runoff algorithm fills a 96–192-column by 9–385-row field and traces upstream
up to 64 steps per cell. It repeatedly interpolates ring geometry, constructs
arrays, computes trigonometry, samples flow, and searches seams. Flow setup uses
four finite-difference surface evaluations per cell. Fields are cached per
`KitMesh`; scene-wide raster sharing occurs later. It does **not** rebuild the
field on every texture sample. Sharing identical keys across hosts is a candidate;
the number of such duplicates and its actual saving have not yet been measured.

Other inclusive hot paths in the same partial profile include ground material
sampling (25.479 seconds), source-PBR sampling (14.058 seconds), and PNG encoding
(10.173 seconds). Inclusive call trees overlap and do not form a stage breakdown.
Component contact detection accounts for only 0.164 seconds in the categorized
samples. A new contact/spatial index is not a priority supported by this profile.

Metal finishes separately evaluate patina for color/material and for bump, even
though patina already computes both. Wrapped pipes evaluate two patina samples
per call. The existing shared sample/bump row mechanism can remove redundant
evaluations at unchanged raster dimensions. Ground sampling also repeatedly
constructs arrays and evaluates invariant transforms and polygon distances.

## Optimization order

1. Share metal material/bump evaluation and measure the remaining raster costs.
2. Replace expensive repeated pipe trace calculations with reusable surface/flow
   data or a cheaper transport algorithm. Preserve gravity direction, periodic
   UVs and finite output; document intentional changes in rust appearance.
3. Move immutable finish preparation and compatible recipe reuse ahead of per-
   receiver sampling. Preserve geometry, material compatibility checks and
   compile-owned cache lifetime. Measure actual duplicate work before adding caches.
4. Reduce per-texel allocation, repeated PBR sampling, and codec overhead. Compare
   decoded pixels when changing lossless encoders; byte identities can change.
5. Investigate edge joining and bulk geometry writes after appearance work falls.
   Preserve holes, collision and navigation. Receiver count alone is not proof
   that binding is slow: the completed binding loop took only 0.275 seconds.
6. Reprofile before a Rust port or parallelization. Unique raster jobs and immutable
   runoff fields are useful worker boundaries. Deduplicate before dispatch and
   bound worker memory; do not serialize large object graphs for each pixel.

The existing viewer uses a 4096² sun shadow map and three 2048² directional sky
shadow maps, with automatic shadow updates disabled. This compiler measurement
does not measure their GPU cost. Retain map resolution; investigate invalidation,
caster culling and draw submission separately if browser profiling identifies them.

[Machine-readable measurements and source identities](kowloon-2026-11-12-profile.json)
retain the completed timing, hashes, partial CPU analysis and snapshot manifest.

`generated/kowloon-profile-20261112/`.

```sh
PROFILE_SECONDS=600 node generated/kowloon-profile-20261112/profile.mjs \
  generated/kowloon-profile-20261112/snapshot \
  generated/kowloon-profile-20261112/repeat
```

Add `--cpu` for sampling; use a separate fresh process for ordinary timings.
No production code or tests changed during this profiling phase. The sub-second
full-fidelity cold-generation target remains unmet.
