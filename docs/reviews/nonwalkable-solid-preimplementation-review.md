# Preimplementation review: solid collision with nonwalkable top

## Ownership and design boundary

The requested behavior has two independent meanings: solid triangles still obstruct a human capsule (including overhead clearance and side walls), but their upward faces must not create walkable navigation support. Model it as an explicit source-level navigation-support semantic for the relevant prop/surface, distinct from `collision=none`/`box`/`solid` and from visibility. Defaults must preserve current behavior. Define its scope for whole asset props, generated collision-box proxies, hidden visual props, dynamic/sealed state and water movement before implementing. Unknown/invalid values should produce source-linked errors, not silently default.

The current `collisionMesh` filters surfaces and `validate.ts` feeds that mesh into Recast; therefore **filtering the nonwalkable solid out of the navigation input is incorrect**: it deletes its clearance/obstacle contribution and can falsely make a low-ceiling route pass. Likewise merely removing output triangles after generation can leave invalid connectivity, erosion and polygon references. A correct approach must retain every physical triangle in Recast's obstruction rasterization while marking the selected triangles as nonwalkable support at the appropriate rasterization stage. The present `generateNavigation` uses `generateSoloNavMesh` for small domains and `generateTileNavMeshData` via chunky-triangle tiles for large domains. Verify that the installed Recast bindings expose per-input-triangle area flags through **both** pipelines before selecting an implementation. If they do not, a principled lower-level adapter is needed; do not fake success by removing collision or invalidating output after the fact. Include overlapping upward faces and overhang lower faces in the design, not just a clipped flat top.

Prop parsing/serialization is in `format.ts`/`props.ts`; compiled triangles carry `Surface` identity; `compiler.ts` hashes surface metadata and geometry, `validate.ts` also computes navigation cache identity and has `NAVIGATION_REVISION`. Preserve per-triangle surface-owner association through mesh selection, transforms, dynamic/sealed and tiled chunky indexing. Make the new behavior part of a stable geometry/navigation hash as appropriate, invalidate the navigation revision/cache when semantics change, and preserve runtime JSON (`toRuntime` surfaces/props), collision GLB and existing rendering. Consider whether any exporters or public API callers need metadata; do not silently imply a destination engine automatically honors nav policy. No collision mesh or visual triangles should be changed by this flag alone.

## Independent behavioral tests required before implementation

1. **Analytic overhead clearance**: a known-size flat walkable floor plus a solid closed overhead box, compare the same geometry flagged walkable/nonwalkable. A 2 m agent under a 1.5 m soffit must fail clearance in both; raising it above the agent restores the lower route in both. Confirm actual collision GLB/mesh and ray or capsule intersection still hit the underside and side. This catches filtering the entire solid out of Recast.
2. **Upper nav island and neighbors**: with enough top area to survive Recast erosion, default solid produces an upper nav component and the explicit nonwalkable variant produces no upper nav triangles. Include an adjacent same-height, independently authored, walkable slab separated by a controlled gap: it must remain represented. Add contiguous/touching surfaces and verify the shared-span behavior; do not erase nearby owner triangles or merge away unrelated floor. Distinguish an unassigned island from a reachable route.
3. **Geometry/collision/export invariance**: roundtrip XML through parse/serialize; compare compiled visible and collision positions/indices and GLB hit geometry across the flag, while surface/runtime metadata and nav outputs reflect the changed semantics. Confirm caller-owned documents/assets are not mutated. For box-proxy props verify the intended owner receives the semantic, not only the visual mesh.
4. **Cache invalidation/recovery**: first bake the ordinary solid, toggle only the support semantic, rebake on the same level/cache path and assert the upper result changes; toggle back and verify recovery. Compare fresh independent compile, navigation `settings.cacheKey` and runtime result. Repeat with output-relevant movement/settings, dynamic open versus sealed states. Never assert only changed hash without changed behavior.
5. **Invalid source**: reject unsupported attribute values and unsupported combinations with source locations; show the next valid compile still works. Test omission/default separately for unchanged behavior. Cover forward/backward XML serialization and public TypeScript API contract without relying on implementation internals.
6. **Both Recast branches**: construct the same local obstacle/floor experiment within a small domain and in a >32m tiled domain; show upper support removed, low ceiling still obstructs and unaffected neighboring walkable areas remain present. Include an obstruction crossing a tile boundary and nonwalking top adjacent to walkable floor to catch loss of triangle-owner mapping through chunky meshes. Verify handling of empty tiles.
7. **Source fidelity boundary**: evaluate a minimal representation of H1 with E as closed collision, assert no E-origin upper nav triangles, and check lower path against actual swept-body/clearance geometry over E's defined footprint. Explicitly record that coverage outside E remains unknown and that the source's real E height/upper access is not proven. Test a deliberately too-low E to ensure physical failure is detected; do not relax the test or create an accepted upper route to make it pass.

Run focused domain tests, typecheck and existing navigation/export/reconstruction suites. Obtain separate independent implementation review, including cancellation/resource cleanup and unchanged water semantics. Current H1's six unassigned triangles are exported nav data but do not prove any connected human-accessible upper path. This review does not authorize accepting or changing that source model.
